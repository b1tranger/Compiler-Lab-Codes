## 1. Token Classification Hierarchy

In compiler lexical analysis, the source text is broken down into categorized token streams:

```
Source Code: "int result = (a + b) * c; if (result >= 100) { result++; }"
                                  │
                                  ▼
                         [Lexical Analyzer]
                                  │
      ┌──────────────┬────────────┼─────────────┬─────────────┬─────────────┐
      ▼              ▼            ▼             ▼             ▼             ▼
  Keywords      Identifiers   Constants     Operators    Delimiters    Ignored
  (int, if)   (result, a, b)  (100, 150)  (=, +, *, >=)  ((, ), ;, {})  (spaces)
                                                │
                 ┌──────────────┬───────────────┼──────────────┬──────────────┐
                 ▼              ▼               ▼              ▼              ▼
            Assignment     Arithmetic       Relational      Logical     Inc / Dec
               (=)           (+, *)          (>=, !=)        (&&)       (++, --)
```

## 2. Key Bugs & Architectural Pitfalls

### A. The Space-Delimited Tokenization Flaw
* **Issue:** Relying purely on whitespace (`if (text[i] == ' ')`) fails on real code like `result++;` or `(a+b)`.
* **Root Cause:** Without spaces, `result++;` is grouped into one token `"result++;"`. It fails the operator check `temp == "++"` and gets misclassified as an identifier.
* **Solution:** Character-by-character scanning matching **2-character operators first** (`++`, `--`, `<=`, etc.), then **1-character operators**, then **alphanumeric identifiers/constants**, and ignoring **delimiters** (`;`, `(`, `)`).

---

### B. Separating Increment (`++`) vs. Decrement (`--`)
* **Issue:** Treating increment and decrement as a single combined `"Increment/Decrement"` group.
* **Fix:** Store them in distinct vectors (`inc` and `dec`) with dedicated branches:
  ```cpp
  else if (temp == "++") { inc.push_back(temp); }
  else if (temp == "--") { dec.push_back(temp); }
  ```

---

### C. `char` Literal vs. `string` Literal Comparisons
* **Issue:** Comparing `temp[j] == "+"` or `temp != '('`.
* **Root Cause:**
  - `temp[j]` is a `char`, while `"+"` is a `const char*` $\rightarrow$ Compile error: `ISO C++ forbids comparison between pointer and integer`.
  - `temp` is a `std::string`, while `'('` is a `char` $\rightarrow$ Type mismatch.
* **Rules:**
  | Target | Syntax | Valid Example |
  | :--- | :--- | :--- |
  | Character check | Single quotes `' '` | `if (temp[j] == '+')` |
  | String check | Double quotes `" "` | `if (temp != "(")` |

---

### D. Boolean Logic: `||` vs. `&&` in Negative Filtering
* **Flawed Code:**
  ```cpp
  // ❌ ALWAYS TRUE (Tautology bug)
  if (temp != "(" || temp != ")" || temp != ";")
  ```
  *Explanation:* If `temp` is `"("`, it is `!= ")"` (true), so the entire `||` expression evaluates to `true`!
* **Corrected Logic:**
  ```cpp
  // ✅ Correctly excludes all specified delimiters
  if (temp != "(" && temp != ")" && temp != ";" && temp != "{" && temp != "}")
  ```

---

### E. Numeric Constant Detection (`all_of` + `::isdigit`)
To identify pure numeric constants (e.g., `100`, `150`) without custom parsing:
```cpp
#include <algorithm>
#include <cctype>

if (!temp.empty() && all_of(temp.begin(), temp.end(), ::isdigit)) {
    con.push_back(temp);
}
```

---

### F. Deduplication: Keeping Unique Identifiers
When an identifier appears multiple times (e.g. `result`), duplicates must be avoided:

1. **Order-Preserving Vector Search (Best for lab reports):**
   ```cpp
   if (find(id.begin(), id.end(), temp) == id.end()) {
       id.push_back(temp);
   }
   ```
2. **`std::set<string>` (Automatically unique, but sorted alphabetically):**
   ```cpp
   set<string> unique_ids;
   unique_ids.insert(temp);
   ```

## 3. Bug Summary Matrix

| Defect / Question | Symptom | Root Cause | Resolution |
| :--- | :--- | :--- | :--- |
| **Combined Inc/Dec** | `++` and `--` lumped together | Single vector & branch | Separate into `inc` and `dec` vectors and branches |
| **Space-Only Splitting** | `result++;` has count 0 for `++` | No space before operator | Use character-level scanning / substring lookahead |
| **Char vs String Literal** | `temp[j] == "+"` fails compile | Type mismatch (`char` vs `const char*`) | Use single quotes `temp[j] == '+'` |
| **Delimiter Exclusion** | Delimiters accepted as identifiers | Used `||` instead of `&&` | Use De Morgan's conjunction: `temp != "(" && temp != ")"` |
| **Numeric Detection** | Numbers classified as identifiers | No digit check | Use `std::all_of(temp.begin(), temp.end(), ::isdigit)` |
| **Duplicate Identifiers** | Same ID listed multiple times | Direct vector push without checking | Check existence using `std::find()` before pushing |

## 4. Single-Line Summaries (For Assignment Report)

You can copy and paste any of these bullet points directly into your assignment documentation:

- **Increment & Decrement Separation:** *Divided unary operators into dedicated `inc` (`++`) and `dec` (`--`) categories with distinct storage vectors and classification counts.*
- **Lexical Token Disambiguation:** *Implemented priority tokenization checking 2-character operators before 1-character operators to eliminate ambiguity between `++`/`--` and arithmetic `+`/`-`.*
- **Punctuation & Delimiter Filtering:** *Applied compound Boolean filtering (`&&`) to isolate non-identifier syntax symbols such as `(`, `)`, `{`, `}`, and `;`.*
- **Numeric Literal Identification:** *Integrated `std::all_of` with `::isdigit` to classify integer constants separately from user identifiers.*
- **Identifier Deduplication:** *Utilized `std::find()` containment checks prior to insertion to maintain unique identifier sets while preserving chronological appearance order.*
- **Keyword Classification:** *Established a reserved-word lookup table to prevent standard C++ control structures (`if`, `else`, `while`, `int`, etc.) from being misclassified as user identifiers.*

### Interaction 2: Increment/Decrement Returns 0 for Real Code Input
* **User Query:** *"the value of inrement and decrement is still 0 for an input: `int result = (a + b) * c; if (result >= 100 && result != 150) { result++; }`"*
* **Diagnosis:** Space-delimited tokenization (`text[i] == ' '`) grouped `result++;` into a single string `"result++;"`, which failed `temp == "++"`.
* **Solution:** Replaced space-based splitting with a full character scanner in `A3.4.cpp`:
  ```cpp
  for (int i = 0; i < text.size(); ) {
      if (isspace(text[i])) { i++; continue; }

      // 1. Multi-character operators first (lookahead)
      if (i + 1 < text.size()) {
          string op2 = text.substr(i, 2);
          if (op2 == "++" || op2 == "--" || op2 == "<=" || op2 == ">=" ||
              op2 == "!=" || op2 == "==" || op2 == "||" || op2 == "&&") {
              op.push_back(op2);
              if (op2 == "++") inc.push_back(op2);
              else if (op2 == "--") dec.push_back(op2);
              else if (op2 == "<=" || op2 == ">=" || op2 == "!=" || op2 == "==") relat.push_back(op2);
              else if (op2 == "||" || op2 == "&&") logic.push_back(op2);
              i += 2;
              continue;
          }
      }

      // 2. Single-character operators
      char c = text[i];
      if (c == '+' || c == '-' || c == '*' || c == '/' || c == '=' ||
          c == '<' || c == '>' || c == '!' || c == '~' || c == '%') {
          string op1(1, c);
          op.push_back(op1);
          if (op1 == "=") assig.push_back(op1);
          else if (op1 == "+" || op1 == "-" || op1 == "*" || op1 == "/" || op1 == "%") arith.push_back(op1);
          else if (op1 == "<" || op1 == ">") relat.push_back(op1);
          else if (op1 == "!" || op1 == "~") logic.push_back(op1);
          i++;
          continue;
      }

      // 3. Identifiers and alphanumeric words
      if (isalnum(c) || c == '_') {
          string word = "";
          while (i < text.size() && (isalnum(text[i]) || text[i] == '_')) {
              word += text[i];
              i++;
          }
          id.push_back(word);
          continue;
      }

      // 4. Ignore delimiters (;, (, ), {, })
      i++;
  }
  ```
