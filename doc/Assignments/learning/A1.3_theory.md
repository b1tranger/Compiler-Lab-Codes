## 1. Core Python Data Structures & Built-in Functions

### A. List Data Structure & Mutability
A list is an ordered, mutable collection of elements defined using square brackets `[]`. In Python, lists automatically resize in memory as elements are added or removed.

```python
# Creating lists
empty_list = []
numbers = [5, 2, 8, 1, 9]

# Accessing elements by index
print(numbers[0])  # Output: 5
```

#### Dynamic Growth Methods:
* `.append(item)`: Adds a single item to the end (index increases by 1).
* `.extend([item1, item2])`: Unpacks an iterable and appends each element individually to the end.
* `.insert(index, item)`: Inserts an item at a specific index, shifting subsequent items to the right.

---

### B. Sorting Lists (`.sort()` vs `sorted()`)

| Method | Behavior | Return Value | Modifies Original? |
| :--- | :--- | :--- | :--- |
| **`.sort()`** | Sorts elements in-place | `None` | **Yes** |
| **`sorted()`** | Returns a new sorted list | New List | **No** |

```python
numbers = [5, 2, 8, 1, 9]

# 1. In-place sorting
numbers.sort()
print(numbers)  # Output: [1, 2, 5, 8, 9]

numbers.sort(reverse=True)  # Descending
print(numbers)  # Output: [9, 8, 5, 2, 1]

# 2. Out-of-place sorting
original = [5, 2, 8, 1, 9]
new_sorted = sorted(original)
print(new_sorted)  # Output: [1, 2, 5, 8, 9]
print(original)    # Output: [5, 2, 8, 1, 9]
```

### C. Dictionaries (`dict`)
A dictionary stores key-value pairs inside curly braces `{}`. Keys must be immutable (e.g. strings, numbers, tuples).

```python
student = {"name": "Alice", "age": 20, "grade": "A"}

# Accessing and modifying values
print(student["name"])  # Output: Alice

student["age"] = 21       # Modify existing key
student["city"] = "Dhaka" # Add new key-value pair
```

### D. The `map()` Built-in Function
`map(function, iterable)` applies a specified function to each item in an iterable and returns a map iterator object.

```python
# Converting string list to integer list
num_str = ["10", "20", "30"]
int_list = list(map(int, num_str))
print(int_list)  # Output: [10, 20, 30]

# Using lambda function with map
numbers = [1, 2, 3, 4]
squared = list(map(lambda x: x**2, numbers))
print(squared)  # Output: [1, 4, 9, 16]
```

### E. Sorting Characters in a String
Strings are immutable in Python. To sort characters in a string, pass the string to `sorted()` (returns a list of single characters) and recombine them with `''.join()`.

```python
text = "compiler"

# sorted(text) -> ['c', 'e', 'i', 'l', 'm', 'o', 'p', 'r']
sorted_text = "".join(sorted(text))
print(sorted_text)  # Output: ceilmopr
```

## 2. Python Loop Patterns (`for` & `while`)

### A. `for` Loop Iteration Patterns
```python
words = ["eat", "tea", "tan"]

# 1. Direct value iteration
for word in words:
    print(word)

# 2. Index iteration using range(len(...))
for i in range(len(words)):
    print(f"Index {i}: {words[i]}")

# 3. Index and Value iteration using enumerate()
for index, word in enumerate(words):
    print(f"Index {index} -> {word}")

# 4. Dictionary key-value iteration

for key, value in student.items():
```

### B. `while` Loop Syntax & Control Statements

```python
# Basic while loop
words = ["eat", "tea", "tan"]
i = 0
while i < len(words):
    print(f"Index {i}: {words[i]}")
    i += 1  # Increment counter (avoid infinite loops!)

# while with break and continue
i = 0
while i < 10:
    i += 1
    if i == 3:
        continue  # Skip iteration when i == 3
    if i == 7:
        break     # Terminate loop completely when i == 7
    print(i)

# while...else block (Executes only if loop completes without break)
count = 0
while count < 3:
    print(count)
    count += 1
else:
    print("Loop finished successfully without break!")
```

## 3. Membership Operators (`in` / `not in`) & Type Matching

The `in` and `not in` operators test for membership within a collection (lists, dictionaries, sets, strings).

### Usage Examples:
```python
# Example 1: Preventing duplicates in a list
words = ["eat", "tea", "eat", "tan", "tea"]
unique_words = []
for word in words:
    if word not in unique_words:
        unique_words.append(word)
print(unique_words)  # Output: ['eat', 'tea', 'tan']

# Example 2: Substring membership
if "z" not in "compiler":
    print("'z' is absent!")
```

### Critical Membership Gotchas:
1. **Sorted Strings vs Original Strings**:
   Checking `sorted_word not in original_list` will evaluate to `True` because sorted character strings (e.g. `"aet"`) do not equal original words (`"eat"`).
2. **Searching Strings inside Nested (2D) Lists**:
   Checking `"eat" in [["eat", "tea"]]` returns `False` because `"eat"` is a string, whereas `[["eat", "tea"]]` contains list objects.

## 4. Parse Errors & Syntax Gotchas

### A. `Parse error: Expected an expression`
In Python, linters/parsers raise this error when a keyword or operator expects a valid expression or indented block, but receives invalid syntax or an incomplete line.

#### Common Causes & Fixes:
* **Empty Block without `pass`**:
  ```python
  # ❌ Incorrect (causes IndentationError / Parse error)
  if condition:
  
  # ✅ Correct
  if condition:
      pass
  ```
* **Invalid Increment Operator**: Python does **not** support C-style `++` or `--` operators.
  ```python
  # ❌ Incorrect
  gr_cnt++
  
  # ✅ Correct
  gr_cnt += 1
  # or
  gr_cnt = gr_cnt + 1
  ```

## 5. List Indexing & `IndexError`

### `IndexError: list index out of range`
Occurs when attempting to access or modify an index outside the valid bounds of a list (`index >= len(list)`).

#### Scenario & Gotcha:
Incrementing an index pointer `gr_cnt` without calling `.append([])` to grow the parent list will cause an `IndexError` on the next loop iteration.

```python
grouped = [[]]  # len = 1 (valid index: 0)
gr_cnt = 0

gr_cnt = gr_cnt + 1  # gr_cnt is now 1

# ❌ Raises IndexError because grouped[1] does not exist yet!
# grouped[gr_cnt].append("word")

# ✅ Fix: Append a new list before incrementing/accessing
grouped.append([])
```

## 6. List Manipulation: `.append()` vs `.extend()`

Choosing between `.append()` and `.extend()` determines whether a list remains flat or becomes nested (2D).

| Method | Behavior | Output Structure |
| :--- | :--- | :--- |
| **`.append(element)`** | Adds the item as a **single element** at the end. | **Nested (2D) List** |
| **`.extend(iterable)`** | Unpacks the iterable and appends **each item individually**. | **Flat (1D) List** |

### Code Comparison:
```python
track_append = []

track_append.append(sublist)  # Result: [['eat', 'tea']] -> 2D List
track_extend.extend(sublist)  # Result: ['eat', 'tea']   -> 1D List
```

## 8. Group Anagrams Algorithm Approaches

### Approach 1: Dictionary / Hash Map (Recommended & Most Efficient)
* **Time Complexity**: $O(N \cdot K \log K)$, where $N$ is word count and $K$ is max word length.
* **Space Complexity**: $O(N \cdot K)$

```python
Anagrams = ["eat", "tea", "tan", "ate", "nat", "bat"]
anagram_map = {}

for word in Anagrams:
    sorted_key = "".join(sorted(word))  # e.g., "eat" -> "aet"
    if sorted_key not in anagram_map:
        anagram_map[sorted_key] = []
    anagram_map[sorted_key].append(word)

grouped = list(anagram_map.values())
print(grouped)  # [['eat', 'tea', 'ate'], ['tan', 'nat'], ['bat']]
```

---

### Approach 2: Nested Loops & Flat Tracking List
* **Time Complexity**: $O(N^2 \cdot K \log K)$

```python
Anagrams = ["eat", "tea", "tan", "ate", "nat", "bat"]
copy = ["".join(sorted(w)) for w in Anagrams]

grouped = [[]]
gr_cnt = 0
track = []

for i in range(len(Anagrams)):
    for j in range(len(Anagrams)):
        if Anagrams[j] not in track:
            if copy[i] == copy[j]:
                grouped[gr_cnt].append(Anagrams[j])
                track.extend(grouped[gr_cnt])

    if i != len(Anagrams) - 1 and len(grouped[gr_cnt]) > 0:
        gr_cnt += 1
        grouped.append([])

print(grouped)  # [['eat', 'tea', 'ate'], ['tan', 'nat'], ['bat']]
```

---

### Approach 3: Using Sum of ASCII Values (`ord()`) & Character Counting

#### 1. Basic ASCII Sum Implementation:
```python
Anagrams = ["eat", "tea", "tan", "ate", "nat", "bat"]
ascii_map = {}

for word in Anagrams:
    ascii_sum = sum(ord(char) for char in word)
    if ascii_sum not in ascii_map:
        ascii_map[ascii_sum] = []
    ascii_map[ascii_sum].append(word)

grouped = list(ascii_map.values())
print(grouped)  # [['eat', 'tea', 'ate'], ['tan', 'nat'], ['bat']]
```

> [!WARNING]
> **ASCII Sum Collision Risk**:
> Summing ASCII values can cause false positives (collisions) because different character combinations can yield identical sums.
> * Example: `"ac"` ($97 + 99 = 196$) and `"bb"` ($98 + 98 = 196$) produce the same ASCII sum, but are **not** anagrams!

#### 2. Collision-Free Character Frequency Tuple:
By counting character frequencies into a 26-tuple (for `'a'` through `'z'`), we avoid string sorting and collision risks:

```python
Anagrams = ["eat", "tea", "tan", "ate", "nat", "bat"]
count_map = {}

for word in Anagrams:
    count = [0] * 26  # 26 character slots
    for char in word:
        count[ord(char) - ord('a')] += 1
    
    key = tuple(count)  # Tuples are immutable and hashable keys
    if key not in count_map:
        count_map[key] = []
    count_map[key].append(word)

grouped = list(count_map.values())
print(grouped)  # [['eat', 'tea', 'ate'], ['tan', 'nat'], ['bat']]
```
* **Time Complexity**: $O(N \cdot K)$ (Optimal linear time complexity).

## 9. C++ Implementations & Polyglot Comparison

### A. Pure Brute Force Pairwise Comparison (`A1.3_brute_force.cpp`)
Instead of global hash maps or string manipulation tracking, pure brute force performs pairwise anagram checks across words with a boolean `visited` array.
- **Time Complexity**: $\mathcal{O}(N^2 \cdot K)$ where $N$ is word count and $K$ is string length.
- **Space Complexity**: $\mathcal{O}(N)$ for the visited array.

```cpp
bool areAnagrams(const string &s1, const string &s2) {
    if (s1.length() != s2.length()) return false;
    int count[256] = {0};
    for (char c : s1) count[(unsigned char)c]++;
    for (char c : s2) count[(unsigned char)c]--;
    for (int i = 0; i < 256; i++) if (count[i] != 0) return false;
    return true;
}

vector<vector<string>> groupAnagramsBruteForce(const vector<string> &words) {
    size_t n = words.size();
    vector<bool> visited(n, false);
    vector<vector<string>> grouped;

    for (size_t i = 0; i < n; i++) {
        if (visited[i]) continue;
        vector<string> current_group = {words[i]};
        visited[i] = true;

        for (size_t j = i + 1; j < n; j++) {
            if (!visited[j] && areAnagrams(words[i], words[j])) {
                current_group.push_back(words[j]);
                visited[j] = true;
            }
        }
        grouped.push_back(current_group);
    }
    return grouped;
}
```

### B. Optimal Hash Map with Sorted Key (`A1.3_hash_map.cpp`)

> **Associated Code Implementation**: [`doc/Assignments/A1/A1.3_hash_map.cpp`](file:///d:/GitHub/UITS/Compiler-Lab-Codes/doc/Assignments/A1/A1.3_hash_map.cpp)

Groups words into buckets using the sorted character sequence as an unordered hash key:
- **Time Complexity**: $\mathcal{O}(N \cdot K \log K)$
- **Space Complexity**: $\mathcal{O}(N \cdot K)$

```cpp
vector<vector<string>> groupAnagramsHashMap(const vector<string> &words) {
    unordered_map<string, vector<string>> anagram_map;
    for (const string &word : words) {
        string key = word;
        sort(key.begin(), key.end());
        anagram_map[key].push_back(word);
    }

    vector<vector<string>> grouped;
    for (auto &[key, group] : anagram_map) {
        grouped.push_back(move(group));
    }
    return grouped;
}
```

### E. Why Grouping Anagrams is Drastically Harder in C than C++

Solving **Group Anagrams** in **C** is significantly more challenging, error-prone, and verbose than in **C++** (or Python) due to fundamental architectural gaps in C's standard library:

#### 1. Lack of Dynamic Nested Containers
- **C++**: `vector<vector<string>>` automatically grows, allocates, copies, and deallocates memory via RAII.
- **C**: A dynamic 2D array of variable-length strings requires a **triple pointer** (`char***`). You must manually `malloc()` the outer array of groups, `malloc()` each group's string pointers, `malloc()` each individual string's character buffer, track sizes and capacities separately, and recursively call `free()` to prevent memory leaks.

#### 2. Absence of a Standard Hash Map
- **C++**: The optimal $\mathcal{O}(N \cdot K \log K)$ approach takes ~10 lines of code using `std::unordered_map<string, vector<string>>`.
- **C**: The C Standard Library (libc) **has no hash table container**. To implement the hash map solution, a developer must hand-roll:
  1. A string hashing function (e.g., djb2 or MurmurHash).
  2. Collision resolution (linked-list chaining or open addressing).
  3. Dynamic bucket resizing and reallocation.
  4. Memory life-cycle management for all keys and bucket nodes (easily 150+ lines of low-level C code).

#### 3. Cumbersome String Sorting & Comparisons
- **C++**: Strings are objects with operator `==` and iterators: `sort(str.begin(), str.end())`.
- **C**: Characters are raw `char` arrays requiring custom comparator callbacks with `qsort()`:
  ```c
  int compare_chars(const void *a, const void *b) {
      return (*(char *)a - *(char *)b);
  }
  // Sorting requires:
  char copy[100];
  strcpy(copy, word);
  qsort(copy, strlen(copy), sizeof(char), compare_chars);
  ```

#### Architectural Complexity Matrix

| Dimension | C | C++ | Python |
| :--- | :--- | :--- | :--- |
| **Lines of Code (Optimal)** | ~150–200 lines | ~25 lines | ~10 lines |
| **Nested Output Storage** | `char***` (triple pointer + manual `realloc`) | `std::vector<std::vector<std::string>>` | `list[list[str]]` |
| **Hash Table** | Must be coded from scratch | Built-in (`std::unordered_map`) | Built-in (`dict`) |
| **String Sorting** | `qsort()` with custom comparator function | `std::sort()` one-liner | `"".join(sorted(s))` |
| **Memory Management** | Manual (`malloc` / `realloc` / `free`) | Automatic (RAII) | Automatic (Garbage Collected) |

### F. C++ Range-Based `for` Loops over Vectors and Maps

> **Associated Code Implementations**:
> - [`Lab_Codes/Courtesy/SadiaIslam/similar[A1.3].cpp`](file:///d:/GitHub/UITS/Compiler-Lab-Codes/Lab_Codes/Courtesy/SadiaIslam/similar[A1.3].cpp) (Original courtesy implementation)
> - [`Lab_Codes/Courtesy/SadiaIslam/similar[A1.3]-formatted.cpp`](file:///d:/GitHub/UITS/Compiler-Lab-Codes/Lab_Codes/Courtesy/SadiaIslam/similar[A1.3]-formatted.cpp) (Input-order preserved 2D formatted variant)

In modern C++ (C++11 and later), the **range-based `for` loop** provides a clean, safe syntax for traversing containers without manual iterator or index management:

$$\text{Syntax: } \texttt{for (declaration : collection)}$$

#### 1. Iterating Over Vectors (`for (string s : st)`)

When traversing a `vector<string> st`:
```cpp
vector<string> st = {"eat", "tea", "tan", "ate", "nat", "bat"};

for (string s : st) {
    // s is a copy of each string in the vector
}
```
- **Type Deduction**: Each element in `st` is a `std::string`.
- **Value vs. Reference**:
  - `for (string s : st)`: Copies each string element by value on every iteration.
  - `for (const string &s : st)`: *(Recommended)* Binds a `const` reference to the existing element, eliminating string memory allocation and buffer copies.
  - `for (string &s : st)`: Binds a mutable reference if you need to modify the elements in-place.

#### 2. Iterating Over Maps (`for (auto pair : mp)`)

When traversing an `unordered_map<string, vector<string>> mp`:
```cpp
unordered_map<string, vector<string>> mp;
// ... populate mp ...

for (auto pair : mp) {
    // pair is std::pair<const string, vector<string>>
    cout << "Key: " << pair.first << endl;
    for (string word : pair.second) {
        cout << word << " ";
    }
}
```
- **Internal Storage**: Associative containers in C++ store key-value pairs as **`std::pair<const Key, Value>`**.
- **Role of `auto`**: The compiler deduces the exact pair type automatically:
  $$\texttt{auto} \implies \texttt{std::pair<const std::string, std::vector<std::string>>}$$
- **Member Access**:
  - `pair.first`: The key (here, the sorted signature `string`, e.g., `"aet"`).
  - `pair.second`: The value (here, the collection `vector<string>` holding anagrams).
- **Performance Caution**:
  - `for (auto pair : mp)` copies the **entire pair** by value, which duplicates the dynamic `vector<string>` heap buffer on every iteration!
  - **Idiomatic Modern C++ (C++17 Structured Bindings)**:
    ```cpp
    for (const auto &[key, group] : mp) {
        // key is const string&
        // group is const vector<string>& (zero copying overhead!)
    }
    ```
