# C++ Concepts & Theory (A3.1 / A3.3)

This document covers compiler design concepts (Lexical Analysis & Token Categorization) alongside core C++ principles: dynamic containers (`std::vector`), character vs. string literals, memory safety, and loop boundary conditions.

---

## 1. Lexical Analysis: Tokens, Lexemes & Operator Classification

In a compiler, the **Lexical Analyzer (Scanner)** is the first phase of the front-end. It reads a stream of characters from the source code and groups them into meaningful sequences called **lexemes**, which are mapped to **tokens**.

```
Source Code: "x = a + b * 2"
               │
               ▼
      [Lexical Analyzer]
               │
               ▼
Tokens: [Identifier: x] [Assignment: =] [Identifier: a] [Arithmetic: +] [Identifier: b] [Arithmetic: *] [Number: 2]
```

### Common Operator Categories

| Category | Operators | Description |
| :--- | :--- | :--- |
| **Assignment** | `=`, `+=`, `-=`, `*=`, `/=` | Assigns values to identifiers/variables |
| **Arithmetic** | `+`, `-`, `*`, `/`, `%` | Performs mathematical calculations |
| **Relational** | `<`, `>`, `<=`, `>=`, `==`, `!=` | Compares two values and yields a boolean result |
| **Logical** | `&&`, `\|\|`, `!` | Evaluates boolean expressions |
| **Bitwise** | `&`, `\|`, `^`, `~`, `<<`, `>>` | Performs bit-level manipulations |

## 2. Dynamic Containers: `std::vector` vs. Raw Arrays

### Why Raw Arrays Failed in `A3.3.cpp`

In C++, raw arrays (like `string id[10]`) have fixed compile-time size and do **not** support object-oriented container methods:

```cpp
// ❌ WRONG: Raw Array
string op[10];
op.push_back("+"); // ERROR: Raw arrays do not have .push_back()
int n = op.size(); // ERROR: Raw arrays do not have .size()
```

Furthermore, declaring `string id[text.size() - 1]` relies on **Variable Length Arrays (VLAs)**:
- VLAs are part of C99, but **not valid standard C++**.
- For non-trivial C++ types (like `std::string`), VLAs can cause memory corruption or undefined behavior.
- If `text.size() == 0`, `text.size() - 1` underflows to `18446744073709551615` (size_t max), causing a crash.

### The Correct C++ Solution: `std::vector<std::string>`

`std::vector` is a dynamic array that automatically grows in size, allocates heap memory safely, and provides container methods:

```cpp
#include <vector>
#include <string>

// ✅ CORRECT: Dynamic Vector
std::vector<std::string> op;
std::vector<std::string> id;

op.push_back("+");   // Appends to the back safely
cout << op.size();   // Returns the exact count of elements (1)
```

## 3. Character Literals vs. String Literals

In C and C++, single quotes and double quotes represent completely different types:

| Syntax | Type | Example | Internal Representation |
| :--- | :--- | :--- | :--- |
| Single quotes `' '` | `char` (scalar integer) | `'~'` | Integer ASCII value (e.g., `126`) |
| Double quotes `" "` | `const char*` (pointer) | `"~"` | Pointer to a null-terminated array `['~', '\0']` |

### The Pointer-to-Integer Comparison Error

```cpp
// ❌ COMPILE ERROR: Comparing char with const char*
if (temp[0] == "~") 
// error: ISO C++ forbids comparison between pointer and integer

// ✅ CORRECT: Compare char with char literal
if (temp[0] == '~')

// ✅ OR: Compare std::string with string literal
if (temp == "~")
```

## 4. Loop Boundaries & Off-by-One Errors

### Why `i < vec.size() - 1` Is a Bug

A standard 0-indexed container with $N$ elements has indices from $0$ to $N-1$.

```cpp
vector<string> op = {"+", "-", "*"}; // size = 3 (indices 0, 1, 2)

// ❌ WRONG: Stops at i < 2, so it only visits i = 0 and i = 1
for (int i = 0; i < op.size() - 1; i++) {
    cout << op[i] << endl; // Misses "*" at index 2!
}

// ✅ CORRECT: Visits all elements (i = 0, 1, 2)
for (int i = 0; i < op.size(); i++) {
    cout << op[i] << endl;
}

// ✅ EVEN BETTER: Modern C++ Range-based for loop
for (const string& item : op) {
    cout << item << endl;
}
```

> [!WARNING]
> If `op` is empty (`op.size() == 0`), `op.size() - 1` underflows because `.size()` returns an unsigned integer (`size_t`). `0u - 1` becomes `18446744073709551615`, causing an out-of-bounds segmentation fault.

## 5. State & Variable Lifetime Across Multiple Passes

In `A3.3.cpp`, the variable `temp` was reset to `""` during token parsing. In the subsequent printing loop:

```cpp
// ❌ WRONG: temp is already "" (empty string) here!
for (int i = 0; i < op.size(); i++) {
    if (temp == "=") { ... } // Never true!
}
```

To categorize stored operators in a second pass, you must inspect each element `op[i]`, not the expired accumulator `temp`.

## 6. Comprehensive Bug Summary for `A3.3.cpp`

| Line(s) | Issue in `A3.3.cpp` | Root Cause | Fix |
| :--- | :--- | :--- | :--- |
| **9** | `string id[text.size()-1], op[...]` | VLA of strings; no member functions | Use `vector<string> id, op, assig, ...` |
| **19, 34, 85** | `temp[0] == "~"` | Comparing `char` (int) with `const char*` | Use `temp[0] == '~'` or `temp == "~"` |
| **21, 24, 28, ...** | `op.push_back(...)` | `.push_back()` does not exist on raw arrays | Fixed automatically by using `vector<string>` |
| **53, 58, 67** | `for (int i=0; i < id.size()-1; ...)` | Skips the last element; underflows if empty | Use `i < id.size()` or range-for loop |
| **69, 74, 80, 85** | `if (temp == "=")` | `temp` is empty `""` after the previous loop | Inspect `op[i]` or print categorized vectors directly |

## 7. Corrected & Idiomatic Implementation

```cpp
#include <iostream>
#include <string>
#include <vector>

using namespace std;

int main() {
    cout << "Enter an expression: ";
    string text;
    getline(cin, text);
    text += " "; // Sentinel space to flush the last token

    vector<string> id;
    vector<string> op;
    vector<string> assig;
    vector<string> arith;
    vector<string> relat;
    vector<string> logic;

    string temp = "";
    for (int i = 0; i < text.size(); i++) {
        if (text[i] == ' ') {
            if (!temp.empty()) {
                // Check if temp is an operator
                if (temp == "=" || temp == "+" || temp == "-" || temp == "*" || temp == "/" ||
                    temp == "<" || temp == ">" || temp == "<=" || temp == ">=" || temp == "!=" ||
                    temp == "==" || temp == "||" || temp == "&&" || temp == "~" || temp == "!") {
                    
                    op.push_back(temp);

                    if (temp == "=") {
                        assig.push_back(temp);
                    } else if (temp == "+" || temp == "-" || temp == "*" || temp == "/") {
                        arith.push_back(temp);
                    } else if (temp == "<" || temp == ">" || temp == "<=" || temp == ">=" ||
                               temp == "!=" || temp == "==") {
                        relat.push_back(temp);
                    } else if (temp == "||" || temp == "&&" || temp == "~" || temp == "!") {
                        logic.push_back(temp);
                    }
                } else {
                    id.push_back(temp);
                }
                temp = "";
            }
        } else {
            temp.push_back(text[i]);
        }
    }

    // Display Identifiers
    cout << "\nIdentifiers (" << id.size() << "):\n";
    for (const string& identifier : id) {
        cout << "  " << identifier << "\n";
    }

    // Display All Operators
    cout << "\nAll Operators (" << op.size() << "):\n";
    for (const string& operator_token : op) {
        cout << "  " << operator_token << "\n";
    }

    // Display Specific Classifications
    cout << "\n--- Operator Classification ---\n";
    
    cout << "Assignment (" << assig.size() << "):\n";
    for (const string& item : assig) cout << "  " << item << "\n";

    cout << "Arithmetic (" << arith.size() << "):\n";
    for (const string& item : arith) cout << "  " << item << "\n";

    cout << "Relational (" << relat.size() << "):\n";
    for (const string& item : relat) cout << "  " << item << "\n";

    cout << "Logical (" << logic.size() << "):\n";
    for (const string& item : logic) cout << "  " << item << "\n";

    return 0;
}
```
