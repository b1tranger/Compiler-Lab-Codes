#include<iostream>
#include<vector>
#include<algorithm>
#include<unordered_map>
using namespace std;

int main(){
vector<string> st = {"eat","tea","tan","ate","nat","bat",};
unordered_map<string,vector<string>> mp;

for(string s : st){
    string temp = s;
    sort(temp.begin(),temp.end());
    mp[temp].push_back(s);
}

for(auto pair :mp){
    for(string word : pair.second){
        cout<<word<<" ";
    }
    cout<<endl;
}
return 0;
}

## 3. Analysis & Key Insights

1. **Problem Identification (Group Anagrams)**:
   - Anagrams are words composed of the exact same characters with identical frequencies, arranged in different orders (e.g., `"eat"`, `"tea"`, `"ate"`).
   - This implementation groups anagrams from a vector of input strings into sub-lists.

2. **Core Technique: Sorted Canonical Signature**:
   - When any two anagrams are sorted character-by-character, their resulting strings become identical:
     - `"eat"` $\rightarrow$ `"aet"`
     - `"tea"` $\rightarrow$ `"aet"`
     - `"ate"` $\rightarrow$ `"aet"`
   - The sorted string acts as the **hash key** in an `unordered_map<string, vector<string>>`.
   - The original unmodified word is appended to the vector under that sorted key.

3. **Bucket Storage Mechanics**:
   - `mp[temp].push_back(s)`: If the key `temp` does not exist yet, `std::unordered_map::operator[]` value-initializes an empty `vector<string>` and appends `s`. If it exists, `s` is appended to the existing bucket.

4. **Time & Space Complexity**:
   - **Time Complexity**: $\mathcal{O}(N \cdot K \log K)$, where $N$ is the number of strings and $K$ is the maximum length of a string.
     - Sorting each string of length $K$ takes $\mathcal{O}(K \log K)$.
     - Map hashing and insertion take $\mathcal{O}(K)$ on average.
     - Total time across $N$ words: $\mathcal{O}(N \cdot K \log K)$.
   - **Space Complexity**: $\mathcal{O}(N \cdot K)$ to store keys and string copies in the hash map.

5. **Modern C++ Style Recommendations**:
   - **Avoid pass-by-value copies in loops**: `for (auto pair : mp)` copies the entire `pair<const string, vector<string>>` on each iteration. Using `const auto& [key, group] : mp` avoids copying dynamically allocated vectors.
   - **Order Non-Determinism**: `std::unordered_map` does not preserve insertion order; bucket order depends on hash values.
