## 3. Analysis & Key Insights

1. **Root Cause 1: Hash Bucket Ordering vs. Insertion Order**:
   - `std::unordered_map` is implemented as an array of buckets indexed by hash values (`std::hash<std::string>`).
   - When iterating with `for (auto pair : mp)`, elements are traversed in bucket order, which depends on hash values modulo bucket count, **not insertion order**.
   - As a result, `"abt"` (`"bat"`) hashed to an earlier bucket index than `"aet"` (`"eat"`), causing `"bat"` to print first.
   - **Resolution**: A parallel `vector<string> order` tracks unique keys the moment they are first encountered (`if (mp.find(temp) == mp.end()) order.push_back(temp)`).

2. **Root Cause 2: Unformatted Output**:
   - The original code simply printed space-separated strings followed by `endl`.
   - The expected format is a 2D JSON/Python array representation with enclosing brackets `[]`, quotes `""`, and comma separators `,`.
   - **Resolution**: Implemented two nested indexed loops with `(j + 1 < group.size())` boundary checks for precise comma placement.
