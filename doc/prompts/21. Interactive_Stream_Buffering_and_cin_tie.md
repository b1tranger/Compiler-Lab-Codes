## 3. Analysis & Key Insights

### 1. The Stream Tying Contract in C++
- By default in standard C++, `std::cin` is tied to `std::cout` via `std::cin.tie(&std::cout)`.
- Whenever an extraction (`>>`) is initiated on `std::cin`, the runtime automatically issues `std::cout.flush()`. This guarantees that user prompts (e.g., `out << "Enter count: "`) lacking a trailing newline (`\n` or `endl`) are pushed out of user-space memory buffers onto the physical terminal screen before the application blocks for keyboard input.

### 2. The `detach_C()` Side Effect
- In [`main.h`](file:///d:/GitHub/UITS/Compiler-Lab-Codes/doc/Assignments/A4_b1t_Lang/main.h#L13-L17), `detach_C()` executes:
  ```cpp
  ios_base::sync_with_stdio(false);
  cin.tie(NULL);
  cout.tie(NULL);
  ```
- Untying `std::cin` (`cin.tie(NULL)`) terminates the automatic pre-read flush guarantee.
- Because `out << "How many numbers do you want to calculate? ";` does not terminate with `\n` or `std::endl`, the character bytes remain buffered in `cout`'s user-space buffer.
- `in >> count` blocks immediately, causing the terminal to appear blank or hung. Only when an explicit newline/flush is later output (or on program exit) does the accumulated prompt flush, appearing out of order.

### 3. CP Batch Mode vs. Interactive CLI Mode
- **Competitive Programming (Batch)**: Large dataset throughput is critical; prompts do not exist, and I/O is piped from judge files. `cin.tie(NULL)` provides a 2x-5x speedup by eliminating unnecessary flushes.
- **Interactive CLI Software**: Human usability depends on visible prompts prior to input blocking. Untying `cin` breaks interactive console ergonomics.
