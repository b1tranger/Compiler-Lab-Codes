## 3. Analysis & Key Insights

1. **Compilation Failures**:
   - `std::getline` requires `std::basic_istream` as its first parameter and `std::string` as its second. Inverting arguments causes an immediate overload resolution failure.
   - Passing `char` into a function expecting `std::string` fails without an explicit string conversion, and comparing `std::string == char` has no matching standard comparison operator.

2. **Accidental Assignment in Conditionals**:
   - `else if (flag = false)` silently assigns `false` to `flag` and evaluates to boolean false, completely suppressing the `INVALID` output branch and hiding parsing errors from the user.

3. **Syntactic Constraints of Infix Grammars**:
   - In pure infix arithmetic, binary operators require operands on both sides. Hence, an operator's follow-set must include either an operand (digit) or an opening sub-expression delimiter `(`.
   - Restricting the follow-set exclusively to `NUM` fatally rejects parenthesized sub-expressions like `2*(3+4)`.

4. **Dyck Language Parenthesis Invariant**:
   - Simply checking whether the final count of `(` equals `)` allows inverted strings like `2+3)(4+5` to pass. A valid parenthesis string must maintain non-negative open-bracket depth at every prefix.
